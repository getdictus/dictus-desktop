# Phase 11 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Revision R2 — Unified Engine Picker (2026-06-02, gap-closure, post-UAT)

**Supersedes the two-surface layout** (separate "Local Model Library" section at the
top + an abstract "Embedded (local)" radio in the ProviderPicker). UAT showed the two
surfaces were not understood as one decision, and "Embedded" had a hidden dependency on
the library's active model. Approved direction: **the model IS the engine.**

**New information architecture — one section "Post-traitement":**

- A **single tabbed list**: `Sur l'appareil` (default, prominent) / `Cloud` (de-emphasized,
  labelled "données envoyées"). No silent cloud fallback — unchanged principle.
- **On-device tab is one ordered list of selectable engines:**
  1. **Apple Intelligence** (first — free, native, zero-download; only on macOS Apple Silicon)
  2. **Local GGUF models** as direct engine choices — Qwen2.5 1.5B (recommended), Qwen3 4B,
     TranslateGemma 4B, + any custom imports. Download / progress / delete / custom-import
     live inline on each model row (reuses `ModelCard`).
  3. **Local server (Ollama / LM Studio)** last (advanced).
- There is **no separate library section** and **no abstract "embedded" radio**. Selecting a
  GGUF model row sets `post_process_provider_id = "embedded"` AND `active_llm_model_id =
  <that model>` in one action. A model row's "selected" state = `provider == embedded &&
  active_llm_model == row.id`. Apple / Ollama rows select by `provider == id` as before.
- Selecting a **not-yet-downloaded** model row triggers its download, then auto-selects it
  on completion (the existing auto-activate behaviour).
- The **"Moteur actif" summary card** at the top of the section shows the current engine
  (model name when embedded) with the local/private/offline tags.

Sections of the original contract below describing the separate `LlmLibrarySection` placement
(Layout Contract) and the "Embedded provider selection + no-model flow" are retained for
history but **superseded by this revision** for layout/placement. Visual tokens (spacing,
colour, ModelCard states, GGUF validation) remain in force.

## Spacing Scale

Declared values (all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps (`gap-1`), badge padding (`px-1`), inline chip spacing |
| sm | 8px | Compact element spacing (`gap-2`, `p-2`), card inner gaps, progress bar height (`h-2`) |
| md | 16px | Default element spacing (`p-4`, `gap-4`), card padding |
| lg | 24px | Section padding (`space-y-6`), settings group gaps |
| xl | 32px | Layout gaps between major settings groups |
| 2xl | 48px | Not used in settings context (page-level only) |
| 3xl | 64px | Not used in settings context |

Exceptions (justified, single):
- Drop-zone minimum hit area: 44px height — touch/pointer target accessibility floor (WCAG 2.5.5)

**Source:** Observed from `ModelsSettings.tsx`, `ModelCard.tsx`, `PostProcessingSettings.tsx` — reuse verbatim.

> Note: the existing `ModelCard.tsx` progress bar ships at `h-1.5` (6px). This phase standardizes the LLM library progress bar to `h-2` (8px) to keep the spacing scale to multiples of 4. The 8px bar remains visually thin and conforms to the contract.

## Typography

Exactly 2 weights declared: 400 (regular) and 500 (medium). Emphasis is carried by size contrast (`text-base` vs `text-sm`), never by a third weight.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`text-sm`) | 400 (regular) | 1.5 (`leading-relaxed` on descriptions) |
| Label | 12px (`text-xs`) | 400 (regular) | 1.5 |
| Heading (section) | 14px (`text-sm`) | 500 (`font-medium`) | 1.4 |
| Heading (page) | 20px (`text-xl`) | 500 (`font-medium`) | 1.2 |

Typography rules enforced by this phase:
- Model name in card: `text-base font-medium` — size contrast (16px vs 14px body) carries the emphasis, not weight
- Model description in card: `text-sm text-text/60 leading-relaxed`
- Progress percentage / speed: `text-xs tabular-nums text-text/50`
- Section sub-headings ("Your Models", "Available Models"): `text-sm font-medium text-text/60`
- Badge text: `text-xs font-medium`
- Inline empty-state body: `text-sm text-mid-gray`

> Note: the existing `ModelCard.tsx` uses `text-base font-semibold` (weight 600) for the card name. This phase replaces every `font-semibold` with `font-medium` (weight 500) in the LLM library surface, relying on the `text-base`/`text-sm` size step for name emphasis. This keeps the phase to a strict 2-weight contract.

**Source:** `ModelCard.tsx` lines 139, 160, 248-250; `ModelsSettings.tsx` lines 225, 341; `PostProcessingSettings.tsx` line 652.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#fbfbfb` light / `#0a1628` dark (`var(--color-background)`) | Page background, card background |
| Secondary (30%) | `mid-gray/10` to `mid-gray/20` overlays (`var(--color-mid-gray)` = `#808080`) | Card border, section divider, inactive badge fill, drop-zone background |
| Accent (10%) | `#6ba3ff` (`var(--color-logo-primary)`) | See reserved-for list below |
| Destructive | `danger-ghost` variant (implicit red — existing Button variant) | Delete model action only |

Accent (`logo-primary / #6ba3ff`) reserved for:
1. Active model card border (`border-logo-primary/50`) and background tint (`bg-logo-primary/10`)
2. "Active" badge and "Recommended" badge fill/border
3. Download progress bar fill
4. "Embedded (local)" provider selected-state highlight in ProviderPicker
5. Inline empty-state link ("download a model below") underline/hover
6. "Custom" badge outline variant (secondary/outline — inherits `logo-primary` tint)
7. Focus ring on file-picker drop-zone (`focus:ring-logo-primary`)

Secondary (`mid-gray`) reserved for:
- Card border in non-active, non-downloading state: `border-mid-gray/20`
- Drop-zone dashed border: `border-dashed border-mid-gray/40` (matches existing placeholder in PostProcessingSettings line 644)
- Metadata text (size, speed, status): `text-text/50` or `text-mid-gray`
- "Custom" model badge background: `bg-mid-gray/10 text-mid-gray`

Destructive (`danger-ghost` Button variant) reserved for:
- Cancel download button inside ModelCard progress row
- Delete model button in card footer row

**Source:** `App.css` CSS variables, `ModelCard.tsx`, `PostProcessingSettings.tsx` lines 644-663.

### LLM Library card states (mirrors ModelCardStatus)

| State | Visual |
|-------|--------|

| State | Visual |

### Embedded provider states (in ProviderPicker row)

| State | Visual |
|-------|--------|
| No model downloaded | `EmbeddedNoModelEmptyState` inline below provider row (text + scroll-link to library) |
| Model downloaded, not active | Row selectable; no extra content |

### Loading state (library init)

## Interaction Contract

### Model card click behavior

| Card state | Click target | Result |
|------------|-------------|--------|
| `downloadable` | Anywhere on card | Triggers download |
| `available` | Anywhere on card | Sets as active LLM |
| `active` | Anywhere on card | No-op (already active) |
| `downloading` | Cancel button | Cancels download; card returns to `downloadable` |
| `active` or `available` | Delete button (footer) | Opens OS native `ask()` dialog (same pattern as transcription model delete) |

### Custom GGUF import behavior

1. User clicks "Add custom model" button → `tauri-plugin-dialog` file picker opens, filter `.gguf`
2. OR user drags a file onto the drop-zone
3. Backend validates 4-byte GGUF magic header
4. **Valid:** file copied to `$APP_DATA/models/`; card appears in library with Custom badge; status = `available`
5. **Invalid:** `Alert variant="error" contained` renders inline below drop-zone; no card created; drop-zone returns to idle state

### Embedded provider selection + no-model flow

1. User selects "Embedded (local)" in ProviderPicker
2. If no LLM is downloaded: `EmbeddedNoModelEmptyState` appears inline under the provider row
3. "Download a model" link in empty state scrolls to and highlights the `LlmLibrarySection` (same page, anchor scroll, no modal, no navigation)
4. Qwen2.5-1.5B card is visually highlighted to indicate recommendation:
   - **Default:** accent border pulse animation, 1 cycle (`border-logo-primary`, brief opacity/scale pulse), then settles to a static accent border
   - **`prefers-reduced-motion: reduce`:** skip the pulse entirely — render a static accent border (`border-logo-primary/50`) only, no animation. The recommendation is still conveyed by the persistent accent border.
5. Once user downloads and activates a model: empty state disappears; provider row shows normal selected state

### Active model indicator

- Only one LLM can be active at a time
- Active card: `border-logo-primary/50 bg-logo-primary/10` with Active badge
- Selecting a new model: previous active card transitions to `available` state; new card transitions to `active`
- Sort order: active model pinned to top of "Your Models" section (mirrors `ModelsSettings.tsx` sort logic)

### No-model library state (no LLMs downloaded at all)

"Your Models" sub-section is hidden. Only "Available to Download" section is shown with 3 catalogue cards. "Add custom model" button and drop-zone are always visible regardless of downloaded count.

## Layout Contract

The `LlmLibrarySection` replaces the placeholder card at the top of `PostProcessingSettings` (currently `~line 638`). It is a `SettingsGroup` with:

```
SettingsGroup (title = "Local Model Library")
  ├── [description paragraph — text-sm text-mid-gray]
  ├── [loading spinner OR]
  ├── "Your Models" sub-header (text-sm font-medium text-text/60) — hidden if empty
  │   └── ModelCard × N (downloaded + active models)
  ├── "Available to Download" sub-header (text-sm font-medium text-text/60)
  │   └── ModelCard × 3 (catalogue, not yet downloaded)
  └── CustomGgufDropZone
      ├── Button "Add custom model" (variant=secondary, size=md)
      └── Drop-zone div (dashed border, 44px min-height, centered label)
```

Max width: `max-w-3xl w-full mx-auto` — inherits from PostProcessingSettings outer container.

Space between ModelCards: `space-y-3` — matches ModelsSettings.

Space between sub-sections: `space-y-6` — matches PostProcessingSettings.
