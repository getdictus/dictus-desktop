<objective>
Close the shortcut-capture and shortcut-management gaps from 13-UAT.md (test 3, BLOCKER + MAJOR + MINOR).

- GAP 3 (BLOCKER): multi-key combos like Cmd+1 "appear then disappear" and never bind. Root cause confirmed: the chip (like the old GlobalShortcutInput) waits for `keyPressed` to drain to length 0 on keyup before committing. On macOS the OS swallows keyup for non-modifier keys while Cmd (meta) is held, so the array never empties and the combo never commits. Bare digits work because no modifier swallows their keyup. Fix: commit the combo on the FIRST non-modifier keydown while modifiers are held (the proven pattern), instead of waiting for all keyups.
- GAP 4 (MAJOR): there is no way to remove a bound shortcut. Add a visible clear button that calls the new `clearSmartModeBinding` command (added in 13-05).
- GAP 6 (MINOR): the shortcut control renders as its own full-width row; redesign as a compact, right-aligned chip consistent with the app's existing shortcut UI. Concrete styling guidance is provided inline in Task 1 step 8 (reuse the existing app chip + icon-button classes) — no external design tooling is needed.

Locked decisions honored: single-key bindings ARE allowed; set/edit/delete follow top-tier shortcut UX (research folded into the action below).

Purpose: shortcut binding becomes reliable and fully manageable (set / edit / clear) with a compact control.
Output: a reworked `SmartModeShortcutChip.tsx` with keydown-commit capture, an inline clear affordance, and a compact layout; 3 new i18n keys propagated to all 20 locales.
</objective>
