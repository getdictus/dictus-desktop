  <name>Task 1: Chip suspends ALL global shortcuts during capture</name>
  <files>src/components/settings/post-processing/SmartModeShortcutChip.tsx</files>
  <action>
Wire the chip to suspend ALL global shortcuts while recording and resume them on every exit path (UAT test 7).

1. On record start in `handleClick` (~183): replace the current best-effort per-binding suspend block
   ```ts
   if (currentBinding) { commands.suspendBinding("smart_mode_" + modeId).catch(() => {}); }
   ```
   with a global suspend:
   ```ts
   commands.suspendAllShortcuts().catch(() => {});
   ```
   (Keep `setIsRecording(true)` after.) This silences every OS hotkey so an already-bound combo is captured by the webview keydown listener instead of firing its action.

2. Add a single resume helper and call it on EVERY exit path:
   ```ts
   const resumeAll = () => { commands.resumeAllShortcuts().catch(() => {}); };
   ```
   Call `resumeAll()` in:
   - `commitCombo` (~70): after the command resolves — on BOTH success and conflict branches (i.e. after setConflict/onBound). Replace the existing `commands.resumeBinding("smart_mode_"+modeId)` restore-on-conflict call with `resumeAll()` (resume-all re-registers the previous binding too, since it iterates all bound shortcuts).
   - `handleClickOutside` (~158): replace the `if (currentBinding) commands.resumeBinding(...)` with `resumeAll()`.
   - effect cleanup (~175, the `return () => { ... }`): call `resumeAll()` so an unmount/early-return during recording cannot leave all globals dead. Guard so resume only runs if a recording was actually in progress (the effect only runs when `isRecording` is true, so calling resume in its cleanup is correct — it fires whenever recording stops or the component unmounts mid-record).

   Net invariant: every transition OUT of `isRecording === true` calls resumeAll exactly once. Avoid double-resume causing errors by relying on resumeAllShortcuts being idempotent (re-registering an already-registered shortcut: the backend `register_shortcut` may warn but must not throw — verify in 13-09 that resume_all logs warn and continues; it does). It's acceptable for resume to run on both commitCombo and the effect cleanup since the backend tolerates it.

3. Remove now-unused `suspendBinding`/`resumeBinding` imports/usages from this file IF they are no longer referenced (the clear path uses clearSmartModeBinding, not resumeBinding). Double-check before removing.

4. handy_keys note (from capture-no-suspend.md): after suspend-all, on the handy_keys implementation the OS hotkeys no longer reach the webview as fired actions, but webview keydown capture also may not see them unless the window is focused. The settings window IS focused while the user clicks the chip, so webview keydown capture is adequate for this UAT scenario. Do NOT add a backend-recording-stream capture path in this plan (scope control) — document in the SUMMARY that handy_keys background-focus capture is a known follow-up if a later UAT shows capture failing while unfocused. The primary defect (existing shortcut FIRING during capture) is fixed by suspend-all on both implementations.
