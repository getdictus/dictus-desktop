<objective>
Close gap [G13] defect (1) at the backend boundary: stop emitting a single hardcoded English conflict sentence that conflates two distinct UX situations.

Today `find_conflicting_binding` (src-tauri/src/shortcut/mod.rs ~1197) returns only `Option<String>` (the conflicting binding id) — it does not signal WHICH of its three overlap rules matched. `set_smart_mode_binding` (~1405) then builds one hardcoded sentence `format!("This shortcut is already used by: {}", other_name)` for every case, and the chip renders it verbatim (always English, never distinguishing exact-duplicate from base-key collision).

This plan makes the backend return a STRUCTURED, machine-parseable conflict error carrying (a) a stable error code, (b) the conflicting binding's display name, and (c) the conflict KIND, plus the base combo for the base-key case. No finished English prose crosses the boundary. The frontend localization mapping is plan 13-21.

This establishes the reusable pattern for translating backend-originated user-facing errors (a [G13] explicit goal in STATE.md decisions 2026-06-08).

Purpose: a translatable, situation-specific shortcut conflict message.
Output: `ConflictKind` enum, an updated `find_conflicting_binding` returning the kind, and a codified `BindingResponse.error` payload from `set_smart_mode_binding`.
</objective>
