  <files>src-tauri/src/shortcut/mod.rs</files>
  <action>
Fix the picker identity split at its root: `add_smart_mode` (mod.rs ~1072) currently ALWAYS mints `format!("mode_{}", timestamp)` and pushes, defeating dedup and splitting identity (UAT gaps test 4 + test 9).

Change `add_smart_mode` to be dedup-aware against the seeded template catalogue:

1. Compute the set of seeded ids from `settings::smart_mode_templates()` (map id → template). The picker passes a template's `name`, `kind`, `prompt`, `target_language` — but NOT its id (the command signature has no id param, keep it that way for back-compat). Detect a seeded template by matching the incoming `name` against each template's name AND `kind` equality. (Use the template catalogue's stored English names; the frontend localizes display but sends `template.name` from the catalogue per SmartModeTemplatePicker.handlePickTemplate, which passes `template.name`.) If multiple match, prefer exact (name, kind) match.

2. If the incoming mode matches a seeded template id `seed_id`:
   - If a mode with `id == seed_id` ALREADY exists in `settings.smart_modes`: OVERWRITE it in place (update name/prompt/target_language) and return that existing mode. Do NOT push a duplicate, do NOT mint a timestamp id. This gives the "re-import overwrites" behavior the user expects (UAT test 4b).
   - If no mode with `id == seed_id` exists yet: insert the new mode using `id = seed_id` (NOT a timestamp). This makes re-adding a previously-deleted seeded template reuse its stable id, so its binding key is deterministic and the card↔binding identity never splits (UAT test 9).

3. If the incoming mode does NOT match any seeded template (a genuine Custom mode from the inline form): keep the existing behavior — mint `format!("mode_{}", chrono::Utc::now().timestamp_millis())` and push.

Add a small pure helper for testability, e.g.:
```rust
/// Resolve the stable id for a created mode. Returns Some(seed_id) when (name, kind)
/// matches a seeded template, else None (caller mints a timestamp id).
pub fn resolve_seeded_id(name: &str, kind: &settings::SmartModeKind) -> Option<String> {
    settings::smart_mode_templates()
        .into_iter()
        .find(|t| t.name == name && &t.kind == kind)
        .map(|t| t.id)
}
```
Then in `add_smart_mode`, branch on `resolve_seeded_id(&name, &kind)`.

Keep the return type `Result<settings::SmartMode, String>` unchanged. Keep `update_smart_mode` and `set_active_smart_mode` unchanged.

NOTE on Decision [13-07] ("addSmartMode/new id to avoid delete-then-recreate collisions"): the original concern was id collision when recreating a deleted default. The overwrite branch (2) handles the "still exists" case explicitly, and the reuse branch handles the "was deleted" case — so reusing the seed id is now SAFE and is in fact required to fix the identity split. Document this reversal in the SUMMARY.

**Part A — delete_smart_mode binding cleanup (UAT test 6).** `delete_smart_mode` (mod.rs ~1116) removes the mode from `smart_modes` via `delete_mode_in_place` but never frees the binding. Fold in the same cleanup `clear_smart_mode_binding` performs, in ONE read/modify/write so it cannot leave a half-cleaned state:

```rust
pub fn delete_smart_mode(app: AppHandle, id: String) -> Result<(), String> {
    let binding_id = smart_mode_binding_id(&id);
    let mut settings = settings::get_settings(&app);

    // Remove the mode first (also reassigns active id). Errors (last-mode / not-found) bail early.
    delete_mode_in_place(&mut settings.smart_modes, &mut settings.smart_mode_active_id, &id)?;

    // Unregister the OS shortcut if one is bound, then drop the binding entry entirely
    // (entry-removal, not empty-set, so init_shortcuts never re-registers it).
    if let Some(b) = settings.bindings.get(&binding_id).cloned() {
        if !b.current_binding.trim().is_empty() {
            if let Err(e) = unregister_shortcut(&app, b) {
                error!("delete_smart_mode: failed to unregister '{}': {}", binding_id, e);
            }
        }
    }
    settings.bindings.remove(&binding_id);

    settings::write_settings(&app, settings);
    Ok(())
}
```
Make sure `unregister_shortcut` and `error!` are in scope (they are already used by `clear_smart_mode_binding` in the same file).

**Part B — reconcile dangling smart_mode_* bindings on load (UAT test 9 blocker).** A persisted `smart_mode_{id}` binding whose `id` is no longer present in `settings.smart_modes` keeps registering and firing invisibly (the orphaned `mode_email` case). Add a pure reconciliation helper to settings.rs and call it from the load path AFTER migration so it also catches seed-reduction orphans:

```rust
/// Remove any bindings["smart_mode_*"] whose mode id is not present in smart_modes.
/// Prevents orphaned smart-mode shortcuts from registering/firing invisibly.
/// Returns true if any binding was removed (settings mutated).
pub fn reconcile_dangling_smart_mode_bindings(settings: &mut AppSettings) -> bool {
    let live_ids: std::collections::HashSet<String> =
        settings.smart_modes.iter().map(|m| m.id.clone()).collect();
    let before = settings.bindings.len();
    settings.bindings.retain(|key, _| {
        match key.strip_prefix("smart_mode_") {
            Some(mode_id) => live_ids.contains(mode_id),
            None => true, // not a smart-mode binding — keep
        }
    });
    settings.bindings.len() != before
}
```
In `load_or_create_app_settings` (settings.rs ~1044): after `migrate_settings_if_needed(&mut settings)` runs (and is persisted), call `reconcile_dangling_smart_mode_bindings(&mut settings)`. If it returns true, persist the cleaned settings (use the same write path the migration uses — match the existing "write back if migrated" pattern; if migration already triggers a write, OR the two booleans so a single write covers both). Verify the exact write mechanism in load_or_create_app_settings and mirror it.

IMPORTANT: reconciliation runs at LOAD, before `init_shortcuts` iterates `smart_modes × bindings`, so the orphaned `smart_mode_mode_email` binding is gone before registration — it can no longer fire. This is the structural fix for the blocker.

```rust
/// Temporarily unregister ALL global shortcuts (used while the user records a new
/// smart-mode shortcut so an already-bound combo is captured, not fired).
#[tauri::command]
#[specta::specta]
pub fn suspend_all_shortcuts(app: AppHandle) -> Result<(), String> {
    let impl_ = settings::get_settings(&app).keyboard_implementation;
    unregister_all_shortcuts(&app, impl_);
    Ok(())
}

/// Re-register all global shortcuts after recording ends (commit/conflict/cancel/unmount).
#[tauri::command]
#[specta::specta]
pub fn resume_all_shortcuts(app: AppHandle) -> Result<(), String> {
    // Re-register every currently-bound shortcut (skip cancel — dynamic) for the active impl.
    let settings = settings::get_settings(&app);
    for (id, binding) in &settings.bindings {
        if id == "cancel" { continue; }
        if binding.current_binding.trim().is_empty() { continue; }
        if let Err(e) = register_shortcut(&app, binding.clone()) {
            warn!("resume_all_shortcuts: failed to re-register '{}': {}", id, e);
        }
    }
    Ok(())
}
```

Do NOT re-register empty bindings.
