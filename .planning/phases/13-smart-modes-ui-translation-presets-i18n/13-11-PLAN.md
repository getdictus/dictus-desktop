The picker must detect when a seeded template is already present among the CURRENT modes (by name, not id) and warn before overwriting.

1. In SmartModeCard.tsx, export the existing `SEEDED_MODE_DEFAULT_NAME` map (add `export` to the `const SEEDED_MODE_DEFAULT_NAME` declaration at line ~29) so the picker can reuse it. Keep `SEEDED_MODE_ID_TO_I18N_KEY` export as-is.

2. In SmartModeTemplatePicker.tsx, change dedup from id-based to NAME-based. The picker already loads `commands.smartModeTemplates()`. It also needs the current modes' names. The simplest reliable source: fetch current modes inside the picker, OR derive presence from the parent. Prefer fetching current modes when the picker opens to avoid prop plumbing:
   - In the `useEffect` that runs on `open`, after loading templates, also call `commands.listSmartModes()` and store `currentModes` in state.
   - Compute, per template, whether a current mode with the SAME display name exists:
     ```ts
     const currentNames = new Set(
       currentModes
         .filter((m) => m.kind === kind)
         .map((m) => {
           // localize seeded names the same way the card does, so a localized
           // pristine seed matches the template's localized name
           const i18nKey = SEEDED_MODE_ID_TO_I18N_KEY[m.id];
           const seedDefault = SEEDED_MODE_DEFAULT_NAME[m.id];
           if (i18nKey && seedDefault && m.name === seedDefault) return t(i18nKey);
           return m.name;
         }),
     );
     const alreadyAdded = currentNames.has(getTemplateName(template));
     ```
   - Replace the dead `existingModeIds.includes(template.id)` with this `alreadyAdded`. (You may keep the `existingModeIds` prop for compatibility but it is no longer the dedup source — note it as unused or remove its use.)

3. Keep the visual "added" badge gated on `alreadyAdded` (it now actually shows). Do NOT disable the button — re-importing IS allowed but must warn.

4. In `handlePickTemplate(template)`, when `alreadyAdded` is true, confirm before overwriting:
   ```ts
   const handlePickTemplate = async (template: SmartMode) => {
     const exists = currentNames.has(getTemplateName(template));
     if (exists) {
       const ok = await ask(
         t("smartModes.picker.overwriteConfirm", { name: getTemplateName(template) }),
         { title: t("smartModes.picker.overwriteTitle"), kind: "warning" },
       );
       if (!ok) return;
     }
     const res = await commands.addSmartMode(
       template.name, template.kind, template.prompt, template.target_language ?? null,
     );
     if (res.status === "ok") { onCreated(); onClose(); }
   };
   ```
   Import `ask` from `@tauri-apps/plugin-dialog` (same import SmartModeCard uses). The backend (13-09) overwrites the existing seeded-id mode when the name+kind matches, so no separate update call is needed — addSmartMode IS the overwrite.

5. Recompute `currentNames` once per render from state (memoize with useMemo if needed) so both the badge map and handlePickTemplate use the same source.
