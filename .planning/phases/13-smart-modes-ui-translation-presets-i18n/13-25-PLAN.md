<objective>
[G16] Close the residual UAT defect where the shortcut-conflict message interpolates the RAW ENGLISH seed mode name (e.g. "Déjà utilisé par : Clean Up") instead of the localized label ("Déjà utilisé par : Nettoyage").

Root cause (confirmed by inspection):
- Backend `set_smart_mode_binding` (mod.rs ~1419-1442) builds the payload from `other_name` = the conflicting binding's STORED name, which for seeded Smart Modes is the English seed name. It discards the stable `other_id` it already computed.
- Frontend `localizeBindingError` (SmartModeShortcutChip.tsx 59-72) interpolates `name` VERBATIM into the t() string.
- The localized label is currently a frontend-only render in `SmartModeCard.displayName` (lines 71-77), keyed off the EXPORTED `SEEDED_MODE_ID_TO_I18N_KEY` + `SEEDED_MODE_DEFAULT_NAME` maps.

Fix: carry the conflicting binding's stable id in the payload, factor the card's localization rule into ONE shared helper, and have the chip resolve the localized label from the id before interpolation.

Purpose: All on-screen text — including the interpolated mode name — must be in the app language (user requirement, MODE-05 + L10N-01).
Output: localized conflict-mode name for both exact-duplicate and base-overlap, with DRY shared helper and a backend payload-format unit test.
</objective>

    ```typescript
    import type { TFunction } from "i18next";
    /**
     * Localized display name for a Smart Mode.
     * Seeded-and-pristine (stored name still equals the English seed default) -> t(i18nKey).
     * Renamed seeded mode or user-created mode -> the literal stored name.
     */
    export function localizeSmartModeName(
      modeId: string,
      storedName: string,
      t: TFunction,
    ): string {
      const i18nKey = SEEDED_MODE_ID_TO_I18N_KEY[modeId];
      const seedDefault = SEEDED_MODE_DEFAULT_NAME[modeId];
      if (i18nKey && seedDefault && storedName === seedDefault) return t(i18nKey);
      return storedName;
    }
    ```

    2. In `SmartModeShortcutChip.tsx`:
    - Import the helper: `import { localizeSmartModeName } from "./SmartModeCard";` (TFunction is already imported at line 3).
    - Rewrite `localizeBindingError` (lines 59-72) to parse the NEW field order and resolve the localized name:
    ```typescript
    /**
     * Backend payloads (from 13-25):
     *   SHORTCUT_CONFLICT|exact_duplicate|<id>|<name>
     *   SHORTCUT_CONFLICT|base_overlap|<id>|<name>|<base>
     *
     * <id> is the conflicting binding id. For smart_mode_* ids we resolve the
     * LOCALIZED mode label (seeded-and-pristine -> t(key), else stored name).
     * Core ids (transcribe/cancel) fall back to the stored <name> verbatim
     * (core binding names are not localized — known limitation).
     */
    function localizeBindingError(
      raw: string | null | undefined,
      t: TFunction,
    ): string {
      if (raw && raw.startsWith("SHORTCUT_CONFLICT|")) {
        const parts = raw.split("|");
        const code = parts[1] ?? "";
        const id = parts[2] ?? "";
        const name = parts[3] ?? "";
        const base = parts[4] ?? "";
        const displayName = id.startsWith("smart_mode_")
          ? localizeSmartModeName(id.slice("smart_mode_".length), name, t)
          : name;
        if (code === "base_overlap") {
          return t("smartModes.card.shortcutConflictBase", {
            name: displayName,
            base,
          });
        }
        return t("smartModes.card.shortcutConflict", { name: displayName });
      }
      return raw ?? t("smartModes.card.shortcutConflict", { name: "" });
    }
    ```
    Note: `id.slice("smart_mode_".length)` strips the `smart_mode_` prefix so e.g. `smart_mode_mode_clean_up` -> `mode_clean_up`, which is the key in `SEEDED_MODE_ID_TO_I18N_KEY`. Do NOT add new i18n keys — `shortcutConflict` / `shortcutConflictBase` already exist in all 20 locales; only the interpolated `{{name}}` value changes.
