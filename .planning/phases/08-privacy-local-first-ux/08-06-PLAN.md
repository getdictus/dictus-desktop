<objective>
Close the UAT design gap on test 9 (cloud providers too visible, page is provider-first instead of model-first). Reframe the Post-Processing settings page per the `mockups/local-first-models-vision.png` mockup: introduce an OFF-by-default `enable_cloud_providers` setting that hides cloud providers behind a toggle; surface the page as "Modèles et traitement local" with a status badge, subtitle, privacy-tagged selected model card, coming-soon library placeholder, and a three-pillar privacy block at the bottom.

Purpose: User feedback (recorded in `08-UAT.md` test 9) flagged the previous two-section picker as "too cloud-friendly" — cloud providers should not be visible by default. The page should also be reframed from "provider × model" axis to a model-first, privacy-first surface. This plan delivers the UI-only half of the UAT scope_split; the embedded LLM runtime + GGUF downloader half is deferred to the new "Local-First Models" milestone.

Output:

- New backend setting `enable_cloud_providers: bool` (default false), Tauri command, lib.rs registration, Rust unit test
- Frontend store wiring (settingsStore + useSettings)
- ProviderPicker extension gating external section
- Full PostProcessingSettings page reframe per mockup
- All English i18n keys

**Strategic decisions baked into this plan:**

1. **Library placeholder = "Coming soon" card.** Per UAT scope_split, this is the planner's call. Rationale: the Local-First Models milestone has been explicitly committed to (promoted ahead of v1.3 per user decision 2026-05-22). A small placeholder card previewing the future capability (gemma3:4b, drag/drop GGUF, in-app downloader) sets user expectation, builds anticipation, and frames the current Custom-provider+Ollama path as the bridge — not the destination. An empty page where the library "should be" reads as incomplete; a labeled placeholder reads as intentional.

2. **Cloud-default migration = non-destructive UI notice.** The toggle is a **UI visibility filter only**; it does NOT mutate `post_process_provider_id` or change runtime behavior. For existing users whose persisted `post_process_provider_id` is a cloud provider (e.g., "openai") and whose toggle is OFF (new default), the page renders a small `Alert` notice "Your saved provider is a cloud model. Enable cloud models below to see it, or switch to a local model" — the user keeps control. Confirmed by reading `src-tauri/src/settings.rs:520-528` (`default_post_process_provider_id` already returns `apple_intelligence` or `custom` — both local — for new installs; this concern only affects existing-user upgrades).
   </objective>
