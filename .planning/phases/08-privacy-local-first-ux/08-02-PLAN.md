Endpoint families to document (11 total, in this order):

1. `https://github.com/getdictus/dictus-desktop/releases/latest/download/latest.json`
   - Configured in: `tauri-plugin-updater` via `src-tauri/tauri.conf.json` (Phase 4 work)
   - Trigger: App start (when `update_checks_enabled=true`) + manual "Check for updates"
   - Data sent: HTTP GET; standard User-Agent / Accept headers. No transcribed text, no PII.
   - Disable: Settings → Debug → "Check for Updates" toggle (`settings.update_checks_enabled`)
   - Default: ENABLED

2. `https://blob.handy.computer/*` (16 model URLs — see appendix)
   - Configured in: `src-tauri/src/managers/model.rs` lines 133, 161, 188, 215, 243, 271, 308, 335, 363, 392, 421, 457, 487, 521, 558, 593
   - Trigger: User clicks "Download" on a model card in Models settings or Onboarding
   - Data sent: HTTP GET only; standard headers
   - Disable: Don't download additional models
   - Default: OFF — no model downloads happen without explicit user action
   - Note: `blob.handy.computer` is upstream Handy's CDN. Migration to Dictus-owned CDN is tracked as INFR-01 (deferred). Phase 8 documents the current state honestly.

3. `https://github.com/getdictus/dictus-desktop/releases/latest`
   - Source: `src/components/update-checker/UpdateChecker.tsx:206` — opened via `openUrl()`
   - Trigger: User clicks "View releases" in portable-update dialog
   - Data sent: Browser navigation only; no HTTP from the app itself
   - Disable: N/A (manual user action)
   - Default: N/A

4. `https://api.openai.com/v1/{chat/completions,models}`
   - Configured in: `src-tauri/src/settings.rs:529`
   - Trigger: (a) Auto-fetch models when API key + provider selected; (b) User triggers post-process shortcut
   - Data sent: `Authorization: Bearer <api_key>` + transcribed text + selected prompt
   - Disable: Settings → Advanced → toggle off Post Processing, OR switch to a local provider, OR delete API key
   - Default: OFF (`post_process_enabled=false`)

5. `https://api.z.ai/api/paas/v4/{chat/completions,models}` — same trigger/data/disable shape as #4. Source: `settings.rs:537`

   - Other trigger/data/disable shape matches #4.

    - Trigger: User selects Custom (local) provider + (a) auto-fetch models; (b) post-process shortcut; (c) Test connection button (added in Plan 03)
    - Data sent: Local-only; HTTP request never leaves the device
    - Disable: N/A — local-only
    - Default: OFF until user picks Custom (local)

    - Trigger: User selects Apple Intelligence + post-process shortcut
    - Data sent: On-device; no network
    - Disable: N/A — on-device
    - Default: OFF until user picks Apple Intelligence (default on macOS ARM64 after Plan 01 lands)
