  <how-to-verify>
    Walk through these 8 checks in order. For each, record PASS / FAIL with notes:

    1. **Post-process screen layout (PRIV-01 core)**
       - Open Settings → Post Process tab.
       - If the tab is missing: go to Settings → Advanced → "Post Processing" group → toggle ON. Re-open Settings; the tab should appear.
       - Confirm the screen renders a stacked picker with TWO sections:
         - "On your device" (or its translation) at the TOP
         - "External — data leaves this device" (or translation) BELOW
       - On macOS Apple Silicon: the local section contains TWO rows: `Apple Intelligence` (first), `Custom (local)` (second).
       - On macOS Intel / Windows / Linux: the local section contains ONE row: `Custom (local)`. Section header still visible.
       - External section contains 6 rows in this order: OpenAI, Z.AI, OpenRouter, Anthropic, Groq, Cerebras.
       - Confirm there is NO single flat dropdown anymore.

    2. **Custom (local) polish**
       - Click the Custom (local) row to select it.
       - Confirm the row card becomes accented (blue border + tinted background).
       - Below the radio label (still INSIDE the same Custom row card), confirm two extras render:
         - A caption line starting with "Tip:" containing a clickable `Ollama` link and inline `ollama serve` code style.
         - A "Test connection" button (secondary variant, small size) below the tip.
       - Click the `Ollama` link → confirm the system browser opens to `https://ollama.com`.
       - These extras must NOT appear on any other row (Apple Intelligence, OpenAI, etc.).

    3. **Test connection — success path**
       - With Ollama running locally (`ollama serve` in a terminal), and Custom (local) selected, click "Test connection".
       - Confirm a green success Alert appears with text like "Connected — N models available" (N = actual model count from your local Ollama).

    4. **Test connection — failure path**
       - Stop Ollama (`pkill ollama` or quit the process), wait a moment, click "Test connection" again.
       - Confirm a red error Alert appears with heading "Could not reach http://localhost:11434/v1" (or whatever base URL is set).
       - Confirm a "Details" `<details>` toggle is present and clicking it reveals the raw error message.

    5. **Toggle promotion + Sidebar gating**
       - Open Settings → Advanced. Without enabling the "Experimental" toggle, confirm a "Post Processing" SettingsGroup is visible containing only the Post Processing on/off toggle.
       - Toggle Post Processing OFF; confirm the Sidebar "Post Process" tab disappears.
       - Toggle Post Processing ON; confirm the Sidebar "Post Process" tab reappears.
       - Open the Experimental group; confirm it contains the three remaining entries (Keyboard Implementation, Acceleration, Lazy Stream Close) and NO PostProcessing toggle.

    6. **About panel link (PRIV-02)**
       - Open Settings → About.
       - Confirm the existing "Privacy" entry (linking to getdictus.com marketing privacy page) is still present.
       - Immediately after it, confirm a new "Network surface" entry is visible with a "View privacy doc" button.
       - Click the button → confirm the system browser opens to `https://github.com/getdictus/dictus-desktop/blob/main/docs/PRIVACY.md`.

    7. **Onboarding (PRIV-03)**
       - Delete or rename your settings.json to trigger fresh onboarding (or use Settings → Debug → Reset onboarding if available).
       - Walk through the onboarding flow.
       - Confirm the flow contains the transcription model picker and NO references to post-processing, cloud providers, or external APIs.

    8. **PRIVACY.md on GitHub**
       - Push the branch and open the file on GitHub (or open the local docs/PRIVACY.md in any markdown viewer).
       - Confirm: the table renders with all columns visible; row #2 mentions `blob.handy.computer/*` with footnote; row #6 mentions the legacy OpenRouter Referer; appendix lists all 16 model URLs; no broken syntax.

    Also capture a screenshot of the post-process screen showing the new ProviderPicker (both sections visible). Attach to the phase summary or paste a path here.
