## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps (`gap-1`), inline icon-to-text padding |
| sm | 8px | Compact element spacing, button internal padding sm size (`px-2 py-1`) |
| md | 16px | Default element spacing, button internal padding md size (`px-4`) |
| lg | 24px | Section vertical gap (`space-y-6` = 24px between SettingsGroups) |
| xl | 32px | Layout container padding |
| 2xl | 48px | N/A for this phase |
| 3xl | 64px | N/A for this phase |

Exceptions:
- ProviderPicker rows: 12px inner padding (`p-3`) — between sm and md, consistent with existing settings row padding (`p-2` for SettingContainer). Use `p-3` for the radio row cards to give the description text breathing room.
- SettingContainer default inner padding: `px-4 p-2` (existing convention — do not deviate).
- Section header label (`<legend>`): 8px bottom margin (`mb-2`) before first radio row.
- Gap between the two picker sections ("On your device" / "External"): 16px (`space-y-4` on the wrapper).

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--color-background)` — `#fbfbfb` light / `#0a1628` dark | Page background, SettingsGroup interior, ProviderPicker row default background |
| Secondary (30%) | `var(--color-mid-gray)` — `#808080` | Section legends, captions, borders (`mid-gray/20`, `mid-gray/80`), placeholder text |

| Destructive | `red-600` / `red-500` | Existing `Button` variant="danger" and `Alert` variant="error" — no destructive action is introduced in Phase 8 |

**Accent reserved for:**
- Selected ProviderPicker radio row: `border-logo-primary bg-logo-primary/10`
- Hover state on unselected radio rows: `hover:bg-mid-gray/5` (mid-gray, NOT accent — accent only on selected)
- Ollama tip link (`text-logo-primary hover:underline`)
- `<input type="radio">` accent color: `accent-logo-primary`
- "Privacy & network surface" button: `variant="secondary"` (not accent-colored; consistent with existing About panel buttons)

**Success color (Test connection):** `green-500` / `green-400` via `Alert variant="success"` (existing token — no new color introduced).

**60/30/10 rule applied to ProviderPicker:**
- 60% background: `--color-background` (card background)
- 30% structure: `mid-gray/20` borders between rows, section legend text in `mid-gray`
- 10% accent: only the currently selected row border/tint

```
┌─ External — data leaves this device ──────────────────┐
│  ( ) OpenAI                                           │
│  ( ) Z.AI                                             │

│  ( ) Anthropic                                        │
│  ( ) Groq                                             │
│  ( ) Cerebras                                         │

```

**Row states:**

| State | Border | Background | Text |
|-------|--------|------------|------|
| Unselected | `border-mid-gray/20` | `bg-background` | `text-text` |
| Unselected hover | `border-mid-gray/20` | `bg-mid-gray/5` | `text-text` |
| Selected | `border-logo-primary` | `bg-logo-primary/10` | `text-text` |
| Disabled (entire picker) | — | opacity-50, cursor-not-allowed | — |

**Section legend:** `text-xs font-medium text-mid-gray uppercase tracking-wide` — matches existing `SettingsGroup` title style exactly.

**Platform behavior:** On platforms where Apple Intelligence is unavailable (macOS Intel, Windows, Linux), the "On your device" section renders only `Custom (local)`. The section header remains. No greyed-out Apple Intelligence row.

**Spacing:**
- Outer gap between sections: `space-y-4` (16px)
- Inner gap between rows within a section: `space-y-1` (4px)
- Row internal padding: `p-3` (12px)
- Radio-to-label gap: `gap-3` (12px)

## Interaction Contract

### ProviderPicker — radio selection

- Clicking anywhere in a row card triggers `onChange(option.value)`.
- The native radio `<input>` is inside the label element — click propagates naturally.
- No keyboard trap. Tab cycles through radio inputs. Arrow keys move between radios within the same `<fieldset>` (native browser behavior).
- Selection is persisted immediately on click via `handleProviderSelect` → `commands.setPostProcessProvider`. No "Save" step.

### PostProcessingToggle — promotion from Experimental

- Moved to a standalone `SettingsGroup` titled `settings.postProcessing.toggle.group` (new i18n key, planner picks exact key) in `AdvancedSettings.tsx`.
- The toggle itself is unchanged (`ToggleSwitch` component, existing binding to `post_process_enabled` setting).
- No visual change to the toggle; only its parent group changes.
- Sidebar "Post Process" tab visibility is unchanged (reads `settings.post_process_enabled` directly — no dependency on the toggle's DOM parent).

### Test connection button — interaction flow

1. User selects "Custom (local)" row → Base URL field and Ollama tip appear.
2. User clicks "Test connection" → button becomes `disabled`; status resets to `loading`.
3. On success → `Alert variant="success"` replaces any prior alert, showing model count.
4. On error → `Alert variant="error"` with friendly message + `<details>` for raw error.
5. Status persists until user clicks again or navigates away (no auto-dismiss).

### About panel — "Network surface" link

- Placed as a new `SettingContainer` row directly after the existing `settings.about.privacy` row (marketing privacy policy link).
- Button: `variant="secondary"` `size="md"` — matches existing About panel buttons.
- Click calls `openUrl("https://github.com/getdictus/dictus-desktop/blob/main/docs/PRIVACY.md")` via `@tauri-apps/plugin-opener`. Opens in default browser.

### Platform-aware provider default (new installs only)

- On macOS ARM64: default provider is `apple_intelligence`. The existing "Apple Intelligence unavailable" `Alert` handles the case where the OS does not support it.
- On all other platforms: default provider is `custom`. The Ollama tip and Test connection button are immediately visible to guide setup.
- No UX change for existing users (serde_default only fires for missing fields).

## Accessibility

- All radio rows wrapped in `<fieldset>` with `<legend>` (section header). This provides screen reader context ("On your device" / "External") for each group.
- Radio `<input>` elements have `name="post-process-provider"` shared across both sections (single selection group).
- `<label>` wraps each row card — click target is the full card, not just the radio circle.
- `disabled` rows: `opacity-50 cursor-not-allowed` + `disabled` on the `<input>`. No interaction.
- Test connection `Alert` result: rendered in DOM after user interaction, within the existing focus flow. No ARIA live region required (not time-sensitive).
- Ollama tip link: `cursor-pointer` with `onClick` — not a real `<a href>` since Tauri webview handles navigation. Accessibility: add `role="link"` and `tabIndex={0}` with `onKeyDown` (Enter key triggers `openUrl`) to match keyboard accessibility of other external link buttons in the app.
