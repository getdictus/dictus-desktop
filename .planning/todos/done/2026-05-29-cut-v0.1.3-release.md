## Tag + release sequence (after GO)

1. **Bump version** in both files (must match):
   - `package.json` → `"version": "0.1.3"`
   - `src-tauri/tauri.conf.json` → `"version": "0.1.3"`
   - Run `bun install` if it touches the lockfile.

2. **Commit the bump** on `main`:
   ```
   chore(release): bump version to 0.1.3
   ```

3. **Tag** (follow the convention `v0.1.2` used — see commit `c2e043d` "chore(release): bump version to 0.1.2" for the exact pattern Pierre uses):
   ```bash
   git tag -a v0.1.3 -m "v0.1.3 Polish & Local-First UX

   Key changes since v0.1.2:
   - Local/Cloud tabs in Post-Processing settings
   - Platform-aware default provider (Apple Intelligence on macOS arm64)
   - docs/PRIVACY.md documenting network surface
   - 25 new i18n keys across 19 sibling locales
   - Overlay outro animation
   - cargo clippy -- -D warnings green

   See .planning/MILESTONES.md for full v1.2 milestone summary."
   ```

4. **Push tag**: `git push origin v0.1.3` — this triggers `release.yml` (per memory `reference_ci_workflows.md`: 7-platform build + asset upload + auto-generate latest.json via `includeUpdaterJson`).

5. **Wait for CI to publish the release** (~30-45 min for 7 platforms). Monitor: `gh run watch` or `gh release view v0.1.3`.

6. **Verify auto-updater path** post-release:
   - `curl https://github.com/getdictus/dictus-desktop/releases/latest/download/latest.json` returns the v0.1.3 manifest with valid Ed25519 signatures
   - On a v0.1.2 install, the app's UpdateChecker should detect v0.1.3 within the next check cycle

7. **Release runbook** documented in `docs/RUNBOOK-updater-signing.md` and `docs/VERSIONING.md` — consult these for any signing-related steps or version-convention questions before tagging. Pierre owns the Ed25519 private key (triple-backup: Bitwarden ×2 + iCloud age-encrypted).
