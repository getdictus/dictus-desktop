## Tech Debt (non-blocking, needs review)

### Cross-cutting — CLI signal semantic regression — ✅ RESOLVED (2026-06-09, commit b80d00a)
`signal_handle.rs:30` mapped `SIGUSR1 → "transcribe_with_post_process"`. After v1.2→v1.3 migration that binding is removed from settings, so `--toggle-post-process` / `SIGUSR1` fired the **legacy** post-process pipeline against a frozen `post_process_prompts` snapshot and bypassed Smart Mode routing — silently diverging from the user's active Smart Mode (functional, non-crashing, but wrong prompt).

**Fix applied (decided: fix, not document):** `send_transcription_input` now re-routes the legacy id to `smart_mode_{active_id}` via the pure, unit-tested `resolve_effective_binding` helper, running the same pipeline as pressing the active mode's shortcut. Plain `transcribe` (SIGUSR2 / `--toggle-transcription`) is untouched; falls back to the legacy id only when no active Smart Mode exists. 3 unit tests added; `cargo clippy --lib -- -D warnings` exits 0. CLAUDE.md flag table + design notes updated. MODE-01 semantics closed; TRANS-02 now signal-triggerable when the active mode is a translation preset.

### Phase 10 & 11 — Nyquist validation incomplete
Both VALIDATION.md files are `status: draft`, `nyquist_compliant: false`, `wave_0_complete: false`. Same pattern as v1.2 (whose phases 6–9 also shipped with draft VALIDATIONs). Run `/gsd:validate-phase 10` and `/gsd:validate-phase 11` to close retroactively.

### Phase 11 — Runtime GPU smoke pending
Windows-x64 and Linux release-build runtime inference (download → load → embedded inference with Vulkan offload / CPU fallback) were not human-smoked. CI build/link is green on those platforms. User accepted as non-blocking for opening Phase 12. Tracked in 11-VERIFICATION human_verification.

### Phase 11 — Catalogue content drift
ROADMAP SC-1 / MDL-01 name 3 models (Qwen3-4B, Qwen2.5-1.5B, TranslateGemma-4B); code ships 4 (Qwen2.5-1.5B, Gemma-3-4B, Phi-4-Mini, Llama-3.2-3B) after a documented post-UAT refresh (TranslateGemma dropped — see memory). Capability satisfies MDL-01; only the model list changed. **Recommend** syncing ROADMAP/REQUIREMENTS wording.

### Phase 13 — MODE-02 seed count vs wording
`default_smart_modes()` seeds **only Clean Up** on first run (deliberate 13-05 UAT decision for a safe default). The other 9 curated modes ship as `smart_mode_templates()` and are one-click-addable via the template picker. MODE-02 intent ("ships ~10 curated modes + safe Clean Up default") is satisfied; the literal "default" seeded count is 1. **Recommend** syncing MODE-02 / ROADMAP wording to "ships 10 curated modes (Clean Up seeded, rest via picker)."
